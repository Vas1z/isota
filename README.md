# isota — 2D MOBA prototype

Пародия на Dota 2 в 2D. Прототип: меню с выбором из 5 героев, LAN-лобби,
атрибуты сила/ловкость/интеллект, способности Q/W/E, магазин, deny,
статистика K/D/A и CS/deny, два трона, крипы, вышки и река по диагонали.

## Установка

```powershell
python -m pip install -r requirements.txt
```

Нужен Python 3.10+ и `pygame-ce`. Проверялось на Python 3.15 + pygame-ce 2.5.8.

## Запуск

### Оффлайн

```powershell
python main.py
```

Откроется **меню**: выбери героя, посмотри статы и способности, нажми
«Играть оффлайн».

`--connect` **не запускает сервер сам** — он только подключается к уже
работающему хосту. Если нужен один компьютер без сети, просто `python main.py`.

### LAN: один игрок хостит, второй подключается

На компьютере хоста:

```powershell
python main.py --host --name Vasya
```

Хост сам напечатает в консоль свой LAN-IP и готовую команду для второго игрока:

```text
LAN-сервер запущен на порту 8765.
IP этого компьютера: 192.168.1.10
Второй игрок: python main.py --connect 192.168.1.10 --port 8765
```

На втором компьютере в той же сети:

```powershell
python main.py --connect 192.168.1.10 --name Petya
```

Откроется **лобби**. Хост видит IP, игроков, их героев и готовность. Каждый
выбирает героя и нажимает «Я готов», затем хост — «Начать игру».

Можно вообще не использовать CLI: в меню есть кнопки «Создать LAN-лобби» и
поле «IP или IP:порт» + «Подключиться».

Если пишет `WinError 10061` или `timed out` — сервер не запущен, указан не тот
IP или брандмауэр блокирует порт. Проверь, что на хосте действительно идёт
`python main.py --host` (или `python server.py`), и разреши Python в
брандмауэре Windows для частной сети. Для оффлайна: `python main.py`.

### LAN: отдельный сервер

Терминал 1:

```powershell
python server.py --host 0.0.0.0 --port 8765
```

Терминалы 2 и 3 (или другие компьютеры):

```powershell
python main.py --connect 127.0.0.1
python main.py --connect 192.168.1.10
```

Полезные флаги:

```powershell
python server.py --max-players 4   # 2v2
python main.py --host --max-players 4
python main.py --connect 192.168.1.10 --port 9000
```

## Управление

| Действие | Клавиша |
|---|---|
| Идти / атаковать | ПКМ |
| Deny своего крипа < 40% HP | ПКМ по своему крипу |
| Способности | `Q`, `W`, `E` |
| Прицеливание способности | ЛКМ после `Q/W/E` |
| Магазин | `B` |
| Остановиться | `S` |
| Двигать камеру | стрелки |
| Двигать камеру | зажать СКМ и тащить |
| Fullscreen | `F11` |
| Скрыть/показать UI | `O` |
| Dev-консоль | `~` или `F1` |
| Выход | `Esc` |

`data/controls.json` пока описывает раскладку, но обработка ввода всё ещё
захардкожена в `game.py`. Это следующий кандидат на рефакторинг.

## Спрайты крипов

Клиент автоматически подхватывает:

```
assets/creep_melee_a.png       # крип сил света
assets/creep_melee_b.png       # крип сил тьмы
assets/heroes/<hero_id>.png    # портреты 5 героев
assets/items/<item_id>.png     # иконки 5 предметов
```

PNG должны быть с альфа-каналом. Клиент обрезает прозрачные поля, масштабирует
спрайт под текущий zoom и рисует его вместо круга. Если файлов нет — остаётся
старая круглая заглушка. После генерации спрайтов в консоли можно выполнить
`reload_sprites`, чтобы не перезапускать игру.

Спрайты уже созданы отдельным агентом. В этом окружении `pygame.image.load`
не всегда может открыть PNG из-за `libpng16-16.dll`, поэтому клиент
автоматически использует Pillow как fallback (он есть в `requirements.txt`).

## Лог агентов в отдельном окне

Самое простое:

```powershell
agents.bat
# или
python agents_console.py
```

Окно показывает `logs/agents.log` в реальном времени. Агент пишет туда одной
командой:

```powershell
python agent_log.py "Subagent-A" "рисую портреты героев"
```

Из игры то же окно открывает команда `agents` в dev-консоли.

## Dev-консоль

Открывается/закрывается по `~` (тильда/ё) или `F1`. Пока консоль открыта,
игра не реагирует на мышь и горячие клавиши — весь ввод идёт в командную строку.
`Enter` — выполнить, `Esc` — закрыть, `Tab` — автодополнение, `Up/Down` — история.

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `show_fps true/false` | FPS в HUD |
| `show_ui true/false` | HUD и миникарта |
| `show_grid true/false` | отладочная сетка |
| `show_hitboxes true/false` | хитбоксы юнитов |
| `debug true/false` | сетка + хитбоксы |
| `ping` | отправить ping, результат появится в консоли (`pong: N ms`) |
| `net` | адрес сервера, ping, число снапшотов |
| `status` | режим, игрок, команда, время, FPS, герой |
| `players` | игроки, золото, CS, K/D, респавн |
| `snap` | последний снапшот |
| `thrones` | HP и состояние тронов |
| `match` | идёт матч или уже победа/поражение |
| `reload_sprites` | перечитать `assets/*.png` без перезапуска |
| `zoom 2` | масштаб карты (0.5–8) |
| `center` | центрировать камеру на герое |
| `fullscreen true/false` | полноэкранный режим |
| `clear` | очистить консоль |
| `echo текст` | вывести текст |
| `history` | история команд |
| `agents` | открыть живой лог агентов в отдельном окне терминала |
| `quit` | выйти |

Флаги без аргумента переключаются: `show_fps` = `show_fps true/false`.

> Важно: сервер и все клиенты должны запускаться из одной и той же версии
> проекта. Версия протокола проверяется, а вот `data/*.json` — нет: если у
> игроков разные карты или статы, картинка и баланс разъедутся.

## Что происходит в онлайне

- **Лобби.** Игроки подключаются, выбирают героев, жмут «Готов». Хост видит
  IP и состав, затем нажимает «Начать игру». Матч не стартует сам.
- **Сервер авторитетный.** Клиенты отправляют только команды `move`,
  `attack`, `deny`, `cast`, `buy`, `stop`. Позиции, урон, мана, золото, опыт,
  уровни, предметы, смерти, assist'ы, респавн и конец матча считает сервер.
  В каждом снапшоте есть флаги `over` и `winner`.
- **Тик 30 Гц.** На каждом тике сервер рассылает снапшот состояния.
- **Клиент интерполирует** чужие юниты с задержкой ~60 мс, поэтому движение
  плавное даже при 30 снапшотах в секунду.
- **Предсказания своего героя пока нет.** На LAN задержка почти незаметна,
  но при игре через интернет её стоит добавить.
- **Респавн героя** растёт с уровнем: `5 + (уровень - 1)` секунд.
- **Комната одна на процесс сервера.** Когда все выходят, мир сбрасывается.
  Комнаты по коду и матчмейкинг — следующий этап.

## Структура

```
main.py              запуск клиента (меню / оффлайн / LAN)
server.py            авторитетный headless-сервер: лобби + матч
game.py              клиент: состояние, ввод, камера, рендер, снапшоты
menu.py              меню героев и экран лобби
console.py           внутриигровая dev-консоль
netclient.py         TCP-клиент, JSON-строки
loader.py            загрузка и валидация data/*.json
gfx.py               загрузка PNG (pygame + Pillow fallback)
ui.py                HUD, миникарта, магазин, способности, статистика
agent_log.py         запись активности агентов
agents_console.py    живой лог агентов в консоли
agents.bat           открыть лог в отдельном окне
shared/sim.py        общая симуляция: юниты, способности, предметы, тик
shared/protocol.py   версия протокола, порт, частоты
shared/netutil.py    определение LAN-IP
assets/              крипы, портреты героев, иконки предметов
data/                настройки, карта, юниты, герои, предметы
logs/                agents.log (создаётся автоматически)
```

Оффлайн и онлайн используют **один и тот же** `shared/sim.py`. Оффлайн просто
тикает его локально, онлайн — получает снапшоты с сервера.

## Протокол

TCP, одно JSON-сообщение на строку. Версия протокола — `shared/protocol.py`.

Клиент → сервер:

```json
{"type": "hello", "version": 1, "name": "Vasya"}
{"type": "select_hero", "hero": "archer"}
{"type": "ready", "ready": true}
{"type": "start"}
{"type": "cmd", "seq": 1, "cmd": {"type": "move", "x": 12.5, "y": 8.0}}
{"type": "cmd", "seq": 2, "cmd": {"type": "attack", "target": 42}}
{"type": "cmd", "seq": 3, "cmd": {"type": "cast", "slot": 0, "target": 42}}
{"type": "cmd", "seq": 4, "cmd": {"type": "buy", "item": "boots"}}
{"type": "ping", "t": 12345.6}
```

Сервер → клиент:

```json
{"type": "welcome", "player_id": "p1", "team": "A", "host": "p1", ...}
{"type": "lobby", "host": "p1", "players": [...], ...}
{"type": "match_start", "players": {"p1": {"team": "A", "hero": "knight"}}}
{"type": "snap", "data": {"tick": 100, "time": 3.3, "units": [...], ...}, "events": [...]}
{"type": "pong", "t": 12345.6}
```

## Что стало ближе к Dota

- **Два трона (Ancient).** У сил света и тьмы есть трон по 2500 HP. Разрушение
  вражеского трона завершает матч: победившая сторона видит `ПОБЕДА`,
  проигравшая — `ПОРАЖЕНИЕ`. Мёртвый трон остаётся на карте руинами.
- **По 2 вышки на мид.** Теперь на средней линии по две вышки с каждой стороны,
  всего 14 вышек (7 на команду).
- **Агро вышек.** Вышка сначала стреляет по крипам и только потом по героям.
- **Агро крипов.** Крипы сначала бьют крипов, затем героев, затем вышки.
- **Ranged-крипы.** В каждой волне 4 ближних и 1 дальний крип: у дальнего
  больше радиус атаки, меньше HP, больше золота и опыта.
- **Опыт и уровни.** За смерть вражеских крипов рядом с героем даётся опыт
  всем вражеским героям в радиусе 8 клеток, а не только добивающему.
  Максимальный уровень — 10; за уровень растут HP, урон и броня.
- **Респавн от уровня.** Чем выше уровень героя, тем дольше он возрождается:
  `5 + (уровень - 1)` секунд.
- **Награда за убийство героя.** Убийца получает `150 + 25 × уровень жертвы`
  золота, а все вражеские герои рядом — `100 + 20 × уровень жертвы` опыта.
- **HUD.** Иконка героя, уровень, HP/мана/опыт, сила/ловкость/интеллект,
  урон/броня/скорость/дальность, K/D/A, CS и deny.
- **5 героев.** Рыцарь, лучница, пиромант, ледяная волшебница и берсерк.
  У каждого свой основной атрибут, базовые статы и рост.
- **Атрибуты.** Сила даёт HP, ловкость — броню и скорость атаки, интеллект —
  ману. Основной атрибут добавляет урон.
- **Способности Q/W/E.** Урон по цели, урон по области, лечение и ускорение.
  Мана тратится, кулдаун идёт, сервер проверяет радиус и цель.
- **Магазин.** `B` открывает магазин у базы: ботинки (+скорость), клинок
  (+урон), латы (+броня), кристалл маны, сердце (+HP). Покупка серверная.
- **Deny.** Своего крипа с HP ниже 40% можно добить ПКМ: враг не получает
  золото/CS, а опыт идёт ему в половинном размере.
- **Статистика.** K/D/A, CS (добитые вражеские крипы), deny (свои), assist'ы.
- **Вышки сильнее.** 900 HP, 40 урона, 5 брони и радиус 3.5.
- **Река.** Диагональная река из левого верхнего в правый нижний угол, видна
  и на карте, и на миникарте.
- **Меню и лобби.** Просмотр героев, статов и способностей, создание LAN-лобби,
  IP и ожидание игроков.

## Ограничения текущей базы

- Нет предсказания своего героя, реконсиляции и реконнекта.
- Победа/поражение есть, но без backdoor-защиты, анимации разрушения трона и
  полноценного экрана результатов со статистикой.
- Способности не прокачиваются по уровням — доступны сразу все три.
- Нет тумана войны, нейтральных крипов, рун, предметных рецептов и звука.
- Нет матчмейкинга и интернет-комнат по коду — только прямой LAN/ IP.
- Карта всё ещё плоская top-down: блок `iso` в `settings.json` пока не
  используется. Изометрия — отдельный этап.
- Масштаб (`iso.zoom`) сейчас `4`; его можно менять в `data/settings.json`
  или командой `zoom 2` / `zoom 3` / `zoom 5` в dev-консоли.

## Если не подключается

1. Проверь, что сервер запущен и пишет `listening on`.
2. На хосте разреши Python в брандмауэре Windows для частной сети
   (TCP-порт 8765).
3. Проверь IP: `ipconfig`, IPv4-адрес активного адаптера.
4. Проверь, что оба компьютера в одной подсети и не включён изолирующий
   режим гостевого Wi-Fi.
5. Порт занят? Запусти сервер и клиент с другим `--port`.

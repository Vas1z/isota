# isota — 2D MOBA prototype

Пародия на Dota 2 в 2D. Пока это прототип: одна карта, один герой, крипы,
башни, золото и CS. Сейчас добавлена база для онлайна по LAN.

## Установка

```powershell
python -m pip install -r requirements.txt
```

Нужен Python 3.10+ и `pygame-ce`. Проверялось на Python 3.15 + pygame-ce 2.5.8.

## Запуск

### Оффлайн

```powershell
python main.py
```

### LAN: один игрок хостит, второй подключается

На компьютере хоста:

```powershell
python main.py --host --name Vasya
```

На втором компьютере в той же сети:

```powershell
python main.py --connect 192.168.1.10 --name Petya
```

`192.168.1.10` — IP хоста. Узнать его на Windows можно командой `ipconfig`
(строка IPv4-адрес).

### LAN: отдельный сервер

Терминал 1:

```powershell
python server.py --host 0.0.0.0 --port 8765
```

Терминалы 2 и 3 (или другие компьютеры):

```powershell
python main.py --connect 127.0.0.1
python main.py --connect 192.168.1.10
```

Полезные флаги:

```powershell
python server.py --max-players 4   # 2v2
python main.py --host --max-players 4
python main.py --connect 192.168.1.10 --port 9000
```

## Управление

| Действие | Клавиша |
|---|---|
| Идти / атаковать | ПКМ |
| Остановиться | `S` |
| Двигать камеру | стрелки |
| Двигать камеру | зажать СКМ и тащить |
| Fullscreen | `F11` |
| Скрыть/показать UI | `O` |
| Выход | `Esc` |

`data/controls.json` пока описывает раскладку, но обработка ввода всё ещё
захардкожена в `game.py`. Это следующий кандидат на рефакторинг.

## Dev-консоль

Открывается/закрывается по `~` (тильда/ё) или `F1`. Пока консоль открыта,
игра не реагирует на мышь и горячие клавиши — весь ввод идёт в командную строку.
`Enter` — выполнить, `Esc` — закрыть, `Tab` — автодополнение, `Up/Down` — история.

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `show_fps true/false` | FPS в HUD |
| `show_ui true/false` | HUD и миникарта |
| `show_grid true/false` | отладочная сетка |
| `show_hitboxes true/false` | хитбоксы юнитов |
| `debug true/false` | сетка + хитбоксы |
| `ping` | отправить ping, результат появится в консоли (`pong: N ms`) |
| `net` | адрес сервера, ping, число снапшотов |
| `status` | режим, игрок, команда, время, FPS, герой |
| `players` | игроки, золото, CS, K/D, респавн |
| `snap` | последний снапшот |
| `zoom 2` | масштаб карты (0.5–8) |
| `center` | центрировать камеру на герое |
| `fullscreen true/false` | полноэкранный режим |
| `clear` | очистить консоль |
| `echo текст` | вывести текст |
| `history` | история команд |
| `quit` | выйти |

Флаги без аргумента переключаются: `show_fps` = `show_fps true/false`.

> Важно: сервер и все клиенты должны запускаться из одной и той же версии
> проекта. Версия протокола проверяется, а вот `data/*.json` — нет: если у
> игроков разные карты или статы, картинка и баланс разъедутся.

## Что происходит в онлайне

- **Сервер авторитетный.** Клиенты отправляют только команды `move`,
  `attack`, `stop`. Позиции, урон, золото, смерти и респавн считает сервер.
- **Тик 30 Гц.** На каждом тике сервер рассылает снапшот состояния.
- **Клиент интерполирует** чужие юниты с задержкой ~60 мс, поэтому движение
  плавное даже при 30 снапшотах в секунду.
- **Предсказания своего героя пока нет.** На LAN задержка почти незаметна,
  но при игре через интернет её стоит добавить.
- **Респавн героя**: 5 секунд (настраивается в `data/settings.json`,
  `timing.respawn_time`).
- **Комната одна на процесс сервера.** Когда все выходят, мир сбрасывается.
  Комнаты по коду и матчмейкинг — следующий этап.

## Структура

```
main.py              запуск клиента (оффлайн / LAN)
server.py            авторитетный headless-сервер (без pygame)
game.py              клиент: ввод, камера, рендер, интерполяция снапшотов
console.py           внутриигровая dev-консоль
netclient.py         TCP-клиент, JSON-строки
loader.py            загрузка и валидация data/*.json
ui.py                HUD, миникарта, всплывающий текст
shared/sim.py        общая симуляция: юниты, снаряды, команды, тик
shared/protocol.py   версия протокола, порт, частоты
data/                настройки, карта, юниты, герой
```

Оффлайн и онлайн используют **один и тот же** `shared/sim.py`. Оффлайн просто
тикает его локально, онлайн — получает снапшоты с сервера.

## Протокол

TCP, одно JSON-сообщение на строку. Версия протокола — `shared/protocol.py`.

Клиент → сервер:

```json
{"type": "hello", "version": 1, "name": "Vasya"}
{"type": "cmd", "seq": 1, "cmd": {"type": "move", "x": 12.5, "y": 8.0}}
{"type": "cmd", "seq": 2, "cmd": {"type": "attack", "target": 42}}
{"type": "ping", "t": 12345.6}
```

Сервер → клиент:

```json
{"type": "welcome", "player_id": "p1", "team": "A", ...}
{"type": "snap", "data": {"tick": 100, "time": 3.3, "units": [...], ...}, "events": [...]}
{"type": "pong", "t": 12345.6}
```

## Ограничения текущей базы

- Нет лобби, выбора героя и отсчёта перед матчем — матч стартует с первым
  подключением.
- Нет предсказания своего героя и реконсиляции.
- Нет победы/поражения: базы пока декоративные, Ancient отсутствует.
- Нет тумана войны, предметов, способностей и опыта.
- Карта всё ещё плоская top-down: блок `iso` в `settings.json` пока не
  используется. Изометрия — отдельный этап.
- Масштаб (`zoom: 6`) очень крупный; для нормальной MOBA-картинки его
  придётся уменьшить.

## Если не подключается

1. Проверь, что сервер запущен и пишет `listening on`.
2. На хосте разреши Python в брандмауэре Windows для частной сети
   (TCP-порт 8765).
3. Проверь IP: `ipconfig`, IPv4-адрес активного адаптера.
4. Проверь, что оба компьютера в одной подсети и не включён изолирующий
   режим гостевого Wi-Fi.
5. Порт занят? Запусти сервер и клиент с другим `--port`.
